# 라운지엑스 경영관리 루프

관리회계대장(`라운지엑스_관리회계대장_2026_v2`)의 결론을 **경영관리 루프 5단계**로 재구성한 정적 사이트입니다.
GitHub Pages에 그대로 배포됩니다. 빌드 과정도 외부 라이브러리도 없습니다.

기준: **2026-09-23 · 실적 1~8월**

## 이 사이트가 하려는 것

> 목표를 명확히 하고 → 현재 스코어를 인식하고 → 무엇이 가장 문제인지 공유하고 →
> 그 문제를 풀 전략과제를 세우고 → 실행관리로 지표를 개선한다.

이 루프를 경영진부터 실무진까지 같은 순서로 돌기 위한 도구입니다.
지표를 나열하는 대시보드가 아니라, **결정을 내리기 위한 화면**입니다.

## 화면 구성 — 19페이지 / 5그룹

| 단계 | 페이지 |
|---|---|
| ① 목표수립 | **미션·비전·사업전략·2026 목표** (사업 분류 체계와 월별 상승 기조 포함) |
| ② 사업현황 및 분석 | **세부사업영역별 현황 — 목표 대비 실적** · 전사 현황 · 원인 특정 · 점포별 비교 · 연말 착지 전망 |
| ③ 전략과제 수립 | **점포별 목표 설정(계산기)** · 세부사업별 CSF와 KPI · 전략과제 |
| ④ 실행관리·지표리뷰 | 실행관리 규칙 · baseline 대비 추적 · 루프 운영 규칙 |
| ＋ 부록 | 지표 체계 · 손익분기 배수 근거 · 가맹 게이트 · 관리손익이란 · 상품과 제품의 비용 분담 · 숫자 신뢰도 · 대장 탭 지도 |

주소는 `#/goal`, `#/biz`, `#/plan` 처럼 해시로 구분되므로 특정 페이지를 북마크하거나 링크로 공유할 수 있습니다.

### ② 세부사업영역별 현황

다섯 사업 각각에 1~12월 꺾은선 차트가 붙습니다.

- **회색 점선** — 계획 (44_프로젝션엔진 §F)
- **진한 실선** — 실적 1~8월 (23_경영지표)
- **같은 색 점선** — 예측 9~12월 (최근 3개월 평균 유지, 개선효과 미반영)

차트 아래에 그 사업의 **문제**와 **대표 원인**이 한 쌍으로 붙고, 맨 아래 각주에서
차트만으로는 안 보이는 인사이트 5개를 정리합니다.

### ③ 점포별 목표 설정 — 화면에서 직접 계산됩니다

이 페이지는 읽는 문서가 아니라 **계산기**입니다.

1. **고정값 확정** — 임차료+건물관리비, 로봇 대가, 인건비. 계약으로 묶여 있어 이번 분기에 못 바꿉니다.
2. **목표에서 역산** — `필요 월매출 = (월 고정비 + 목표이익) ÷ (공헌이익률 − 로열티율)`
   - 중간목표: 매장 BEP 전환 (목표이익 0)
   - 최종목표: 가맹 전환 시 점주 월수입 500만원
3. **점포별 유형 선택** — 각 행의 드롭다운으로 `흑자전환 타겟` / `쇼케이스`를 고릅니다.
   - 타겟: 목표배수 2배 초과 → **개선불가 — 폐점**, 2배 이하 → **개선실행**, 1배 이하 → **달성 — 유지**
   - 쇼케이스: 매출 목표 대신 **1일 방문자 수 목표** (= 월 적자 ÷ 30 ÷ 노출 1인당 가치)
4. **역산 입점 기준** — 모델별 관측 최대 월매출에서 허용 자리값 상한을 거꾸로 계산합니다.

상단 컨트롤(판정 기준 · 목표 월수입 · 로열티율 · 폐점 판정 배수 · 노출 단가)을 바꾸면
표 전체가 즉시 다시 계산됩니다. 선택은 브라우저 `localStorage`에 저장되어 다시 열어도 유지됩니다.

### 세부사업 분류

모든 표·차트가 이 단위로만 쪼개집니다.

- **매장운영** — 유인직영 · 무인직영 · 투자모델
- **식자재유통** — 상품(B2B 원부자재) · 제품(로스터리)
- **가맹사업** — 미개시

'직영매장', '무인매장' 같은 상위 묶음은 세 모델의 손익 구조가 전혀 달라 평균이 왜곡되므로 쓰지 않습니다.

### 드릴다운

점선 밑줄이 그어진 파란 단어를 누르면 상세 패널이 열립니다. 현재 10개 —
매출원가 · 판관비 · 별도 추가비용 · 기계렌탈료 · 위탁수수료 · 위탁운영수수료 ·
감가상각비 · 건물관리비 · 원재료원가 · 로봇·자산 부담.

항목을 추가하려면 `data2.js` 의 `LX.drill` 에 키를 하나 넣으면 됩니다.
본문에서 그 단어가 자동으로 버튼이 됩니다.

## 파일 구조

```
index.html    껍데기 (상단바 · 사이드바 · 본문 틀). 내용은 JS가 채웁니다
ledger.css    스타일
ledger.js     라우터 + 렌더러 · 도넛/꺾은선/막대/히트맵 · 드릴다운 (의존성 없음)
data.js       ★ 루프 5단계 데이터. 매달 이 파일을 고칩니다
data2.js      ★ 상세 숫자 (사업별 손익계산서 · 점포별 · 드릴 설명)
README.md     이 문서
```

차트는 외부 라이브러리 없이 Canvas로 직접 그립니다.
디자인 시스템(색·간격·카드·표·배지)은 **XYZ HR Portal의 `hr.css`를 그대로 차용**했고,
본문 글꼴도 같은 Pretendard(jsDelivr CDN)를 씁니다. CDN이 막힌 환경에서는
시스템 한글 산세리프로 자동 대체되며 레이아웃은 그대로 유지됩니다.

## 로열티율

가맹 로열티율 **3%는 확정된 조건**입니다. ③ 페이지의 입력란은 민감도 확인용입니다.

## ④ 전략과제 — 티켓 · 토글 · 드래그 정렬

- 과제 하나가 **티켓 한 장**입니다. 앞면에는 순위·제목·태그와 **핵심 지표 3개**(연환산 손익 · 올해 매출 · 기한)만 보입니다.
- 제목을 누르면 상세(원인 · 담당 · 산출 근거 · 측정지표)가 펼쳐집니다.
- **티켓을 끌어서 순위를 바꿀 수 있습니다.** 회의 중에 경영진이 직접 조정하는 용도이며,
  순서는 브라우저 `localStorage`에 저장됩니다. `순서 초기화` 버튼으로 기본 순서(원인별)로 되돌립니다.
- 정한 순서는 대장 `40_이슈관리`의 **검토 우선순위** 열에 옮겨 적어야 공식 기록이 됩니다.

## 배포 방법

1. GitHub 저장소 루트에 파일 다섯 개를 올립니다.

```bash
cd lx-ledger-site
git add .
git commit -m "경영관리 루프 5단계로 재구성 (2026-09-22 기준)"
git push
```

2. **Settings → Pages** → Source `Deploy from a branch`, Branch `main` / `/ (root)`.
3. 1~2분 뒤 `https://<계정>.github.io/<저장소>/` 에서 열립니다.

### 화면이 안 바뀌면

`index.html` 의 `?v=20260923i` 가 캐시 무효화용입니다. 파일을 고칠 때마다 이 값을 올리십시오.
그래도 옛 화면이 보이면 `Ctrl+Shift+R`(Mac은 `Cmd+Shift+R`)로 강력 새로고침합니다.

### 비공개로 두려면

관리회계 수치가 들어 있으므로 공개 저장소로 올리면 누구나 볼 수 있습니다.
GitHub Pages는 Free 플랜에서 Private 저장소를 지원하지 않습니다. 선택지는 셋입니다.

- 조직 GitHub Team/Enterprise 플랜에서 Private Pages 사용
- 사내 파일서버나 구글 드라이브에 폴더째 올리고 `index.html` 을 여는 방식
- 숫자를 지우고 구조만 공개

## 설계 규칙

- **원인 없는 과제는 올리지 않습니다.** ④의 과제는 전부 ③에서 특정한 원인 세 개 중 하나에 묶여 있습니다.
- **과제에는 기대효과 금액과 산출 근거를 반드시 붙입니다.** 금액이 없으면 우선순위를 정할 수 없습니다.
- **측정되는 지표와 측정되지 않는 지표를 구분해 표시합니다.** 빨간 점이 붙은 지표는 아직 수집 체계가 없습니다.
- **baseline은 수식이 아니라 고정값으로 적습니다.** 실시간 수식은 과거가 계속 바뀌어 효과 검증이 불가능합니다.
- **경영진과 실무진의 진입점을 나눕니다.** 같은 화면을 다 보면 둘 다 안 봅니다. `⑤ 루프 운영 규칙` 에 역할별 페이지를 명시했습니다.
